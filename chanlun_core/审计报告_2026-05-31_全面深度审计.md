### P0-1: 三买结构评分逻辑反转（validate_tech_score.py）

**问题描述**:
`compute_technical_score()` 的趋势结构评分（第 96-116 行）对所有买点类型统一处理，
不区分一买/二买/三买。导致三买在"中枢下沿附近"被错误评定为"安全边际高"(+15)。

```python
# validate_tech_score.py:105-107
if entry_price <= latest_zs.zd * 1.03:  # 接近中枢下沿
    structure_score = 35
    details.append(f"中枢下沿附近买入: 安全边际高(+15)")
```

**缠论理论要求**:
- 一买/二买在中枢下沿 → 确实安全边际高（买入成本低、上行空间大）
- 三买在中枢下沿 → 说明突破已失败，价格跌回中枢内部 → **结构已坏，不是买入时机**

三买的本质是"突破中枢上沿后回踩不破 ZG"。如果现价在 ZD 附近，说明已经跌穿了 ZG 甚至跌回了中枢内部，三买已失效。

**当前修复情况**:
v1.5 新增了第 7 维度 `zs_break_penalty`（第 327-350 行），检测三买跌破 ZD 时扣 -20/-10 分。
但这个修复**不完整**：结构评分在第 105 行已经给了 +15，然后第 340 行扣 -20，净效果是 -5。
而正确的逻辑应该是一开始就不给 +15。

**实际影响**:
以天山铝业(002532)为例（修复前的实测数据）：
- 结构评分：35（中枢下沿）+ 10（底背驰）= 40
- 信号质量：22（三买+中枢底部）
- zs_break_penalty：未触发（修复前没有此维度）
- 总技术分：100+
修复后 zs_break_penalty=-20，但结构评分仍是 35+10=40，加上信号质量 22，仍可达 42+。

**建议修复**:
```python
# 在结构评分段增加买点类型判断
point_level = getattr(buy_point, 'level', 0)
if entry_price <= latest_zs.zd * 1.03:
    if point_level == 3:
        structure_score = 10  # 三买跌回中枢下沿 = 结构已坏
        details.append("三买跌至中枢下沿: 结构已坏(-10)")
    else:
        structure_score = 35  # 一买/二买的正常逻辑
        details.append("中枢下沿附近买入: 安全边际高(+15)")
```

### P0-2: divergence_threshold=1.0 导致假一买过多

**问题描述**:
`generate_analysis.py:62` 的 `divergence_threshold` 默认为 1.0，即"离开段 MACD 面积 < 进入段面积"就判定为背驰，不要求显著衰减。

**实测数据**（来自 a500 选股 Skill 文档）:
上一轮扫描中 9/39 只一买的背驰比 > 70%（近乎平背驰）：
- 平安银行 89.1%、中国平安 87.5%、南方航空 84.6%
- 中国宝安 81.5%、珀莱雅 80.9%、上海机场 76.5%
- 浦发银行 72.1%、奥瑞金 71.0%、宝钢股份 71.0%

这些是**假一买**——MACD 面积只缩小了 10-30%，不是实质性背驰。

**缠论理论要求**:
缠论原文强调背驰是"力度的显著衰竭"，不是"面积稍微变小"。threshold=0.7 意味着离开段面积必须小于进入段的 70%，即衰减超过 30%，更符合"显著衰竭"的含义。

**缓解因素**:
Phase 2 的技术评分（validate_tech_score.py）会通过信号质量维度做二次过滤，部分假一买分数不会很高。但大量假一买浪费了 Phase 1→2 的计算资源，并稀释了候选池。

**建议修复**:
```python
# generate_analysis.py:62
divergence_threshold = 0.7  # 从 1.0 降为 0.7
```
此修复已在 a500-multi-factor-selection Skill 的"已知坑"中记录但标记为"待用户确认"。

### P0-3: 潜一买(等待确认) 在 Phase 2 代理映射中缺失

**问题描述**:
当 pool_screener.py 重建分析器后找不到对应的 BuySellPoint 对象，会回退到 Scanner 缓存买点代理（第 693-706 行）。代理映射表（第 697-698 行）:

```python
_bp.level = {'一买': 1, '二买': 2, '三买': 3,
             '反转后三买': 3, '反转后类二买': 2,
             '类一买(盘整底背驰)': 1, '类一买': 1}.get(c.get('buy_type', ''), 0)
```

但是 `'潜一买(等待确认)'` 和 `'潜一买(上涨趋势,无效)'` **都不在此映射表中**。
当 buy_type 为这两种值时，`_bp.level = 0`（默认值），进入 validate_tech_score.py 的 `else` 分支（第 189 行），获得信号质量分 15 和一个通用标签 `"未知(level=0)"`。

**正确的映射**:
- `'潜一买(等待确认)'` → level=1, confirmed=False
- `'潜一买(上涨趋势,无效)'` → level=1, confirmed=False（虽然 score=0 不会进入 Phase 2，但映射表应完整）

**实际触发概率**:
低。因为大多数情况下 Phase 2 重建的分析器能匹配到相同的买点（recent_buy 不为 None），
代理路径只在买点因日期偏移或分析器差异无法匹配时触发。但一旦触发，评分会严重失真。

**建议修复**:
```python
_bp.level = {
    '一买': 1, '二买': 2, '三买': 3,
    '反转后三买': 3, '反转后类二买': 2,
    '类一买(盘整底背驰)': 1, '类一买': 1,
    '潜一买(等待确认)': 1, '潜一买(上涨趋势,无效)': 1,  # 新增
}.get(c.get('buy_type', ''), 0)
_bp.confirmed = '类一买' not in c.get('buy_type', '') and '潜一买' not in c.get('buy_type', '')
```

### P1-2: validate_tech_score 信号质量评分的 类一买 路径冗余

**问题**:
validate_tech_score.py 第 129-152 行的 signal_quality 评分通过 `point_level` 区分买点类型，
其中 level=1 且 confirmed=False 走"类一买(潜在一买)"路径，扣 8 分。

但在 Phase 2 代理映射（pool_screener.py:697-698）中，
`'类一买(盘整底背驰)'` → level=1。同时 `'类一买' not in '类一买(盘整底背驰)'` → False → confirmed=False。

所以 `类一买(盘整底背驰)` 通过代理后，confirmed=False → 走 signal_quality 的"类一买"路径 → 被扣 8 分。

**但这里面有个理论问题**: validate_tech_score.py 的"类一买(潜在一买)"标签暗示这个买点是
"一买但缺确认"（即 generate_analysis.py 的 confirmed=False 一买），
而 pool_scanner.py 的"类一买(盘整底背驰)"是另一个独立检测路径。
两者虽都通过 confirmed=False 扣分，但理论含义不同，建议在 signal_quality 分支中明确区分。

### P1-3: 二买评分无回调幅度验证

**问题**:
pool_scanner.py 的 scan_stock() 对二买的评分（第 406-411 行）:
```python
if days_ago <= BUY_WINDOW_RECENT:   # 30天
    score = 5
elif bp.level == 2 and days_ago <= BUY_WINDOW_RECENT * 2:  # 60天
    score = 4
```

只检查了时间窗口，没有验证**回调幅度**。二买的可靠性取决于回调是否足够浅：
- 回吐一买涨幅的 38.2% 以内 → 强势二买
- 回吐 50-61.8% → 中性二买
- 回吐超过 61.8% → 弱势二买（可能跌破一买低点）

当前评分未考虑这个维度。不过，generate_analysis.py 的 `_find_second_class_points()` 
确实检查了"不破前低"的条件（第 733 行 `bi_low >= fc_point.price * 0.99`），
但回调幅度的区分没有传递到 Phase 1 评分中。

**影响**: 浅回调和深回调的二买获得相同分数(5分)，但前者可靠性明显更高。

### P1-4: 三买形成中满分条件偏松

**问题**:
pool_scanner.py 第 465-476 行:
```python
if bi_dir == "up" and latest_bi_end > zg * 1.01 and current_price > zg:
    pullback_pct = (latest_bi_end - current_price) / latest_bi_end
    if pullback_pct >= 0.05:    score = 5   # 深回踩
    elif pullback_pct >= 0.03:  score = 4   # 浅回踩
    elif pullback_pct >= 0.02:  score = 3   # 微回踩
```

深回踩 5% 就给满分 5 分。但此时"回踩未成笔"，可能回踩继续深化。
缠论三买要求回踩**不破 ZG 且确认反弹**，而当前代码在回踩仍在进行中就给了满分。

**对比**: 标准三买（已确认回踩不破 ZG）也是 5 分，"三买形成中(未成笔)"也是 5 分——
两者获得相同分数但确认程度不同。这不合理。

**建议**: 三买形成中的满分上限降为 4 分，标准三买(已确认)保持 5 分。

### P2-2: 三买形成中的 elif 链与中枢位置评分重叠

pool_scanner.py 第 465-498 行，三买形成中的 if 分支和第 477 行的 elif 分支有潜在的逻辑重叠：

三买形成中要求 `current_price > zg`，但随后的 elif 中 `0.95 <= price_vs_zs <= 1.05` 
条件可能在某些边界情况下同时满足（虽然 elif 不会执行，但逻辑意图不清晰）。

| 条件 | 覆盖范围 |
|------|---------|
| 三买形成中 | zg < price < (zg / ZG_ratio) 且 bi_dir=up |
| 中枢下沿机会 | zd*0.95 ≤ price ≤ zg*1.05 且 MACD改善 |

两个条件在 `zg < price < zg*1.05` 区间有重叠。由于 if-elif 结构，三买形成中优先，
但如果三买形成中的条件不满足（比如 bi_dir 不是 up），就会跌入 elif，此时 MACD 和价格位置可能触发"中枢下沿机会"而实际上价格在中枢上方。

### P2-3: MACD 面积计算的日期匹配可能有精度问题

`_calculate_macd_area_for_bi()` (generate_analysis.py:314-342) 用笔的开始/结束日期
与 MACD 数据的日期做精确匹配。如果 K 线和 MACD 的日期格式不完全一致（如 datetime vs date），
匹配可能失败，此时回退到近似匹配（`md.date >= bi.start_date`）。近似匹配没有问题，
但如果精确匹配失败且近似匹配也找不到对应索引，函数返回 0.0，可能导致背驰漏判。

### 3.2 从 Phase 1 到 Phase 2 的评分转换

Phase 1 的 0-5 分数只是一个**粗筛**。真正的技术评分在 Phase 2 通过 `compute_technical_score()` 
计算 7 个维度（满分约 105，但上限截断为 100）。两者的关系是非线性的：

- Phase 1 score=5 → Phase 2 tech_score 可能是 60-100（取决于各维度）
- Phase 1 score=4 → Phase 2 tech_score 可能是 45-85
- Phase 1 score=3 → Phase 2 tech_score 可能是 40-75

这种非线性关系合理，因为 Phase 1 只看结构位置和时间窗口，Phase 2 才全面评估。

## 八、结论

系统整体质量较高，经过 v3.0→v3.6.1 的多次迭代修复了大量 bug（共振惩罚方向、一买进入段选取、类一买趋势过滤等）。

其他 P1/P2 问题影响范围有限，可以在下一轮迭代中处理。
