## 一、严重问题（P0/P1，建议立即修复）

### [CRITICAL-1] 共振惩罚公式方向错误 — composite_scorer.py:238

```python
# 当前代码（错误）：
composite += penalty * 0.5   # 弱tech+弱fund反而加分！

# 正确：
composite -= penalty * 0.5
```

**影响**：tech=40, fund=40, alpha=50, news=50 时：
- 错误：基础分43.5 + 惩罚6.5 = 50.0（弱票被奖励）
- 正确：基础分43.5 - 惩罚6.5 = 37.0（弱票被惩罚）

这是评分体系的核心逻辑错误，导致共振惩罚机制完全反转。

### [CRITICAL-2] 一买/一卖的进入段选取偏差 — generate_analysis.py:592-595

```python
for bi in reversed(self.bis):
    if bi.end_date <= last_zs.start_date and bi.direction == 'down':
        enter_bi = bi
        break
```

**问题**：取的是"最后一个中枢的进入段"，而非"趋势第一个中枢的进入段"。

缠论原文（第62课）要求趋势背驰比较的是：
- enter_bi = 趋势**第一个中枢**的进入段（整个趋势的起点）
- leave_bi = 趋势**最后一个中枢**的离开段（整个趋势的终点）

代码比较的是最后一个中枢的进入段 vs 离开段，这更接近"盘整背驰"而非"趋势背驰"。

**影响**：
- 可能将盘整底背驰误判为趋势一买
- 真正的趋势背驰可能被错过
- 这解释了为什么系统检测到大量"类一买(盘整底背驰)"信号

**修复建议**：在 `_identify_trends()` 返回的 trend 中取第一个中枢，用其进入段与最后一个中枢的离开段比较MACD面积。

### [P1-4] 类一买代理confirmed判断逻辑错误 — pool_screener.py:698

```python
_bp.confirmed = c.get('buy_type', '') != '类一买'
```

**问题**：pool_scanner输出的buy_type是 `"类一买(盘整底背驰)"`（含括号后缀），不是精确的 `"类一买"`。
- `"类一买(盘整底背驰)" != "类一买"` → True → confirmed=True ❌

**正确写法**：
```python
_bp.confirmed = '类一买' not in c.get('buy_type', '')
```

**影响**：盘整底背驰在Phase 2重建分析器后，通过代理路径获得与标准一买相同的高评分（signal_score多8分），违背了"类一买应低于标准一买"的设计意图。
