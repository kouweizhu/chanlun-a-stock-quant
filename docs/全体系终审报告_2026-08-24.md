**【A-6】【P1·仅回测模式】二买扫描遇创新低回调不终止**（generate_analysis.py:1010-1015 缺 `else: break`）

## 四、个股分析链路审计（子代理B × 主审复核）

### 4.1 P1 级发现（7项，均已主审抽验关键项）

**【B-01】编排器超时形同虚设**（single_stock_analysis.py:164-174，主审复核属实）
`as_completed()` 不带 timeout 只在完成后 yield，`.result(timeout)` 永不触发——死参数。线程挂死时主进程永久阻塞，历史观测的超时全是外部杀进程。
→ 方案：改 `concurrent.futures.wait(futures, timeout=总预算)`，超时放弃收集并在 JSON 标注 `timeout_abandoned`。

**【B-02】Baostock 并发锁未覆盖 DataManager**（baostock_utils.py:85 vs data_manager.py:442-447，结构属实）
锁只在模块层，靠消费者自觉：akshare_fundamental 持锁✅，但 single_stock_analysis 默认并行场景下两个 DataManager 实例各自 login/查询裸奔❌——正是历史上川投能源 PE=0 串包事故的结构。
→ 方案：把锁下沉到 baostock_utils.ensure_login/query 内部，或 DataManager 所有 bs 调用包 `with BS_SESSION_LOCK:`。

**【B-03】全源采集失败被渲染成「已检查，无负面信号」**（news_scanner:320→check_negative_news:236-240→generate_report:308-312，**主审复核属实**）
scan_news 返回 `(50,"⚠️采集失败:...")` 时，source="多源(⚠️采集失败…)"不以skip开头→负面模块报ok→否决表第4项显示"已检查，无负面信号"，L3利空静默放行。违反自家C3原则。
→ 方案：search_negative 中检测 detail 首行含"采集失败"或"[0源]"→返回 skip_needs_review。

**【B-04】`.source_failed_{code}_{level}.flag` 成功后永不清理**（唯一删除点在罕见路径）
下次数据源恢复无人删flag→Step 2b恢复流程"见flag即跳过30min"被陈旧flag误导。
→ 方案：get_klines 成功落缓存后调用 clear_agent_fallback；或flag加24h过期时间戳。

**【B-05】*ST/负面关键词全文匹配误杀残留两条活路径**（check_negative_news:180-186 **主审复核属实**）
①iwencai有key路径对 title+summary 全文匹配无个股校验（'*ST泉为'出现在行业综述即误杀本股；`"st "`子串还会命中英文best/first）；②generate_report veto#3 对同花顺新闻/Tavily明细行免相关性检查直接扫严重关键词→同行被立案可触发本股"直接回避"。多源分支已修（要求name/code在标题），**修复只落在无key分支**。
→ 方案：iwencai结果逐条加 name/code-in-title 过滤；veto#3 匹配前先过 extract_news_details 相关性过滤。（注：当前无iwencai key，路径①暂休眠，key恢复即激活）

**【B-06】L3 兜底 multi_year 年键混入季报**（hithink_fundamental.py:101-104，**主审复核属实**）
`yr=报告期[:4]` 无 `-12-31` 过滤→Q1累计值占据年度键→analyze_trend 把 Q1 对年报比→"营收持续下降"假信号、trend_correction 污染。
→ 方案：过滤 `报告期.endswith("-12-31")` 再取年度行。

**【B-07】stock_db.py 写入契约文档一半是幽灵键**（:92-122，**主审复核属实**）
SKILL.md 教的 `score/stock_type/veto/note` 键名实际不存在（实际为 composite_score/stock_type_probs/veto_triggered 等）——照文档写入成功但核心列为NULL，随后 query/trend 格式化 None 直接 TypeError 崩溃。
→ 方案：write_record 对缺失 composite_score 显式报错；修订 SKILL.md 键名清单。

### 5.4 子代理C 发现清单（已由主审核验关键项）

**【C-01】【P1】veto/severe 关键词全文匹配批量误杀通道**（composite_scorer.py:146-157 + news_scanner.py:482-506）
`apply_veto()` 只豁免了 ST 系关键词（注释自认"*ST泉为"教训），其余 15 个 veto 词与全部 12 个 severe 词仍对 news_detail **全文匹配**；而 detail 拼装时把 CCTV/东财/Tavily 的**全市场新闻无差别写入**（评分环节有 name 过滤 L416，拼 detail 时没有）。任一日头条出现"立案调查/减持计划"字样→当日所有被扫股票批量误触 veto(grade=D,pos=0) 或 severe(-15+轻仓)。【主审注：与我 M-04 实测的 CCTV 宏观新闻入 detail 是同一根因的两面——打分侧被中性化掩盖，否决侧是真实雷区】
→ 方案：关键词匹配施加"本股名称/代码在同一消息条目内"约束（复用评分段过滤），或 CCTV/涨停池/雪球等全市场源只参与打分不参与 veto。

**【C-02】【P1】Alpha 缺因子股权重不守恒**（alpha_factor_filter.py:140-149，主审数学复核确认）
`w/w.sum()` 只在因子列层面归一一次；某股仅 1/4 因子有值时 mean_rank 上限=该因子权值（如 gtja191_002 的 0.199）→ 映射后 ≈25-35 分 < ALPHA_BUY_THRESHOLD=40 → 被强制轻仓。科创板/次新/停牌股（panel 无 ffill）系统性受压。对照 fund_factors.py:172-180 同场景按个股可用子因子重归一化的正确实现，两处标准不一。
→ 方案：逐行 `sum(w_i×rank_i)/sum(w_i available)`；或有效因子数<全集时回退中性50+标注。

**【C-04】【P2】共振维度"中枢同向+2分"是互斥伪逻辑**（validate_tech_score.py:519-530）
比较的是两级别中枢的绝对价位而非各自运动方向，两条件恒互斥 → 该 +2 分永远拿不到，共振有效上限 18 分。
→ 方案：改为各自与自身前一中枢比较（`m30[-1].zd > m30[-2].zd and daily[-1].zd > daily[-2].zd`）。

**其余 C 项摘要**：C-03 死配置 aggregation（与主审结论一致）；C-05 汇总MD/Excel推荐口径与 generate_reports 不一致（无阈值/can_buy过滤→死链）；C-06 大盘 regime cap 在两个五维重算点被丢弃（弱市仓位可突破上限）；C-07 cleanup 先行删光昨日报告+Phase1 timeout=600 组合风险；C-08 rescore_news.py 是带伪造元数据的废弃脚本（误运行会污染JSON口径）；C-09 新入围补扫警示缺失；C-10 config_loader 默认值 rev_score_threshold=4≠yaml的3；C-11 veto_reasons 死字段；C-12 E-1分支返回dict键名不一致(current_price vs price)；C-13 报告资金面权重文案硬编码；C-14 margin基线含近期5日自身（对比基准稀释）；C-15 陈旧注释群。
