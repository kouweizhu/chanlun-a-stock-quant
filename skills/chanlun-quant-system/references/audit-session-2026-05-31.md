## P0-1: 三买结构评分逻辑反转

**文件**: validate_tech_score.py:105-107

`compute_technical_score()` 的趋势结构评分对所有买点类型统一处理：
```python
if entry_price <= latest_zs.zd * 1.03:
    structure_score = 35  # "中枢下沿附近买入: 安全边际高(+15)"
```

一买/二买在中枢下沿 → 安全边际高（正确）
三买在中枢下沿 → 突破已失败，跌回中枢内部，结构已坏（错误）

v1.5 新增的 zs_break_penalty（-20/-10分）部分补偿但不完整——结构评分先给+15再扣-20，净效果仅-5。

**建议修复**: 在结构评分段加 `if point_level == 3` 分支，三买在中枢下沿时给 structure_score=10 而非 35。

## P0-2: divergence_threshold=1.0 导致假一买过多

**文件**: generate_analysis.py:62

当前: 离开段面积 < 进入段面积 (=1.0) 即判定背驰，不要求显著衰减。
实测: 9/39 只一买的背驰比 > 70%（平安银行 89.1%、中国平安 87.5% 等），非实质背驰。
推荐: 降至 0.7（离开段面积 < 进入段的 70%，即衰减超 30%）。

## P0-3: 潜一买(等待确认) Phase 2 代理映射缺失

**文件**: pool_screener.py:697-698

代理映射表缺少 `'潜一买(等待确认)'` 和 `'潜一买(上涨趋势,无效)'`。
当 Phase 2 分析器无法匹配买点时，潜一买以 level=0 进入评分引擎，获得错误评分。

**建议修复**: 映射表添加 `'潜一买(等待确认)': 1, '潜一买(上涨趋势,无效)': 1`
confirmed 判断改为 `'类一买' not in buy_type and '潜一买' not in buy_type`

## P1-1: 类一买评分表与代码不一致

代码实际: area_ratio≤0.20→4, ≤0.30→3, ≤0.40→2
用户表: 3-4 分（未区分温和背驰=2分，也未提及中枢下移降级=0-2分）

## P1-2: signal_quality 的"类一买(潜在一买)"标签歧义

validate_tech_score.py 第 137 行的标签暗示 confirmed=False 的一买（generate_analysis 产出），
但 pool_scanner.py 的类一买(盘整底背驰)也通过 confirmed=False 走同一条路径。
两者理论含义不同，建议在分支中明确区分。

## P1-3: 二买评分无回调幅度验证

Phase 1 的二买评分仅检查时间窗口（≤30天=5分，≤60天=4分），
未验证回调幅度（回吐 38.2% vs 61.8% 的可靠性差异）。
generate_analysis.py 虽检查了"不破前低"，但回调深度未传递到 Phase 1 评分。

## P1-4: 三买形成中满分条件偏松

pool_scanner.py:465-476
回踩 5% 就给 score=5（满分），与标准三买（已确认回踩不破 ZG）相同。
但此时"回踩未成笔"，可能继续深跌。建议上限降为 4 分。
