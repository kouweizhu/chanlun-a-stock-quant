# 线段中枢实现调试记录 (2026-05-03)

## 三个关键 Bug 及修复

### Bug 1: 线段终点方向不一致

**现象**: 海康威视329K线只产生1个线段（预期7-9个）

**根因**: `find_segments()` 中线段结束点取的是特征序列分型中间元素对应的笔索引：
```python
seg_end = middle_feature.bi_index  # ❌ 错误
```
`middle_feature` 对应的笔方向与线段方向相反，导致线段首尾方向不一致（如向下段以向上笔结束）。

**修复**: 改为取分型**右侧**元素对应笔的**前一根**，确保线段首尾同向：
```python
right_feature = merged_features[pattern[2]]
seg_end = right_feature.bi_index - 1  # ✅ 正确
```

### Bug 2: 特征序列包含处理导致线段无法分割

**两重错误**:

1. **包含方向错误**: 使用了"取最宽范围"(max high, min low)，而非缠论标准的 取低低/取高高。
   - 向上线段（特征序列=向下笔）→ 处理方向"向下" → **取低低**: `high=min(h1,h2), low=min(l1,l2)`
   - 向下线段（特征序列=向上笔）→ 处理方向"向上" → **取高高**: `high=max(h1,h2), low=max(l1,l2)`

2. **递归包含导致级联合并**: 递归处理将所有元素合并成一个，如海康12根笔的6个特征序列元素被合并为1个，无法形成分型。
   - 修复: 改为单次遍历（与K线包含处理一致），不递归。

### Bug 3: 中枢延伸吞并全部线段

**现象**: 2500天(1658K线)产生13个线段但只有1个线段中枢

**根因**: 27笔/120天/5%保护机制只加在了 `apply_expansion()`（中枢扩张阶段），但 `find_segment_zhongshus()` 的**中枢延伸**逻辑没有任何限制。一旦3段形成中枢，所有后续线段都被延伸吞并进同一个中枢。

**修复**: 在中枢延伸 `while` 循环中加入同样的三段保护：
- 段数超限（≥9段）→ 强制切分
- 时间超限（≥120交易日）→ 强制切分
- 无效横盘（波动<5%持续>60日）→ 不纳入延伸

**修复效果**: 
| 数据范围 | 修复前段中枢 | 修复后段中枢 | 段BS |
|---------|:---------:|:---------:|:---:|
| 1200天 792K线 | 1 | 2 | 0 |
| 2500天 1658K线 | 1 | 2 | 1 (SS1) |

## 数据范围要求

线段中枢至少需要1200天（≈5年）日线数据才能产生有意义的中枢结构。500天仅够形成2-4个线段，不足以构建中枢。

## 18只自选股实测 (1200天/792K线)

修复后: 13/18 (72%) 产生段中枢, 恒力石化产生唯一 SB3。
段买卖点仍稀少——线段级别信号天然稀有，这是系统特征而非缺陷。
