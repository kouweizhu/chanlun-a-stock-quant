# 三买核心规则确认

> 2026-05-29 用户纠正记录。此前错误地将闭笔作为突破笔视为bug，被用户纠正。

## 核心规则

**三买只需要两个条件，不需要第三个：**

1. ✅ 任何笔向上突破中枢ZG（包括中枢的最后构成笔/闭笔）
2. ✅ 回抽确认时，回抽低点不跌破ZG

**不需要**的第三个条件：
- ❌ 不要求"突破笔必须是中枢完成后第一个明确在中枢外的向上笔"
- ❌ 不要求"闭笔不能同时作为突破笔"

## 理论依据

缠论原文对三买的定义："第三类买点是在某级别上涨趋势中，一个次级别走势类型向上离开缠中说禅走势中枢，然后以一个次级别走势类型回抽，其低点不跌破ZG。"

这里没有说"离开中枢的走势"不能是中枢的最后一笔。**只要这段走势确实突破了ZG，且后续回抽确认不破ZG，三买就成立了**。闭笔作为中枢构成笔和突破笔，两者不冲突——闭笔是中枢的结构组成，突破ZG是其价格行为特征。

## 常见误区

### 误区1："闭笔不能作为突破笔"

**正解**：闭笔打破了ZG，这件事本身就是"向上离开中枢"。它同时具有两个属性——在中枢结构上是闭笔，在价格行为上是突破。缠论看的是走势结构，不要求离开段必须由"与中枢无关的笔"来执行。

### 误区2："同一个中枢只能有一个三买"

**正解**：同一个中枢可以有多个三买。每次出现新的向上突破ZG→回抽确认不破ZG的序列，就是新的三买。各三买相互独立，都是有效买点。后续三买回抽价格可能更低，性价比反而更高。

### 误区3："三买检测用 `>=` 过滤是bug，应改为 `>`"

**正解**：`b.end_date >= zs.end_date` 是正确的过滤条件，不应改为 `b.start_date > zs.end_date`。使用 `>` 会把中枢结束后第一笔也排除（start_date可能等于或略晚于zs.end_date），导致漏检有效三买。

## 系统当前行为（无需修改）

当前代码在 `_find_buy_sell_points()` 中对**每个中枢只取第一个三买**（`break`），这是一个合理的保守策略：

- ✅ 不会信号泛滥（避免一个中枢出6个三买）
- ⚠️ 但会漏掉**价格更低、性价比更高**的后续三买
- 要不要改成全部收集，取决于用户的实际交易需求

## 误判的鉴别

如果将来有人怀疑三买检测有问题，先确认是以下哪种情况：

| 现象 | 可能原因 | 处理 |
|:----|:--------|:----|
| 三买价格刚好在ZG附近 | 正常（回抽接近ZG不破） | ✅ 有效 |
| 同中枢有多只三买 | 正常（不同时间点的回抽确认） | ✅ 有效 |
| 突破笔start_date < zs.end_date | 可能为闭笔（**正常**） | ✅ 有效 |
| 系统输出三买但你认为应该更晚 | 检查回抽低点是否确实>ZG | 如>ZG则有效 |
