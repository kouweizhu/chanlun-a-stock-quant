# ETF 估值分析工作流

ETF 没有个股的基本面数据（无 ROE/营收/净利润/股息率），需要从**跟踪指数**和**基金运行指标**两个维度获取估值数据。

## 数据源优先级

| 优先级 | 数据源 | 可获取的估值数据 |
|:------:|:------|:----------------|
| 1 | 基金实时API (`fundgz.1234567.com.cn`) | 最新净值、实时估值、估值涨跌幅 |
| 2 | 同花顺新闻 (`news_detail_report`) | 份额变动、规模数据、PB/PE提及 |
| 3 | Tavily搜索 (`mcp_tavily_tavily_search`) | 机构研报中的PE分位、PB值、PEG |
| 4 | 新浪财经/界面新闻文章（Tavily extract） | 分析师观点、估值对比 |
| 5 | 雪球 (`xueqiu.com`) | 折溢价率、实时行情、社区讨论 |
| 6 | 东方财富基金档案 (`fundf10.eastmoney.com`) | 规模、份额历史、阶段涨幅 |
| 7 | Bing搜索 (`mcp_bing_cn_bing_search`) | 补充原始新闻来源 |

## 阶梯式搜索技巧

**问题**：Bing/百度搜索"恒生互联网ETF 估值"会被"恒生银行"严重污染。
**技巧**：用代码+关键指标名 + 引号精确匹配：

```
查询1: "513330" "市盈率" OR "PE" （精确匹配代码）
查询2: "恒生互联网科技业指数" "PEG" "分位"   （指数名而非ETF名）
查询3: "恒生互联网ETF华夏" "市净率" "PB"     （全称+英文缩写）
```

Tavily 对长尾新闻的检索效果优于 Bing，但 Bing 更适合精确URL查找。

## 两个估值维度

### 维度A：跟踪指数估值（核心）

从机构新闻/研报中提取（不依赖API，因为东方财富的港股指数行情API对 HSIII 不返回PE/PB）：

| 估值指标 | 提取来源 | 格式示例 |
|:--------|:---------|:--------|
| PE-TTM | 机构研报/新闻 | "PE-TTM约23.57倍，处于近10年约26.64%的分位" |
| PB | 新闻通稿 | "最新市净率PB为2.38倍，低于指数近1年98.47%以上的时间" |
| PEG | 深度研报 | "前十大重仓股预测PEG中位数为0.83" |
| 全球可比折价 | 券商研报 | "较全球可比互联网指数折价约12%" |

### 维度B：基金运行数据（补充）

从 `fundgz.1234567.com.cn` API 和新闻中提取：

```python
import requests, json, re

# 基金实时净值/估值
url = 'https://fundgz.1234567.com.cn/js/513330.js'
r = requests.get(url, headers={'Referer': 'https://fund.eastmoney.com/'}, timeout=10)
m = re.search(r'jsonpgz\((.+?)\)', r.text)
if m:
    d = json.loads(m.group(1))
    # d: fundcode, dwjz(最新净值), jzrq(净值日期),
    #    gsz(实时估值), gztime(估值时间), gszzl(估值涨跌幅)
```

| 运行指标 | 说明 |
|:--------|:-----|
| 折溢价率 | 实时价 vs 净值。负值=折价，正值=溢价 |
| 跟踪误差 | 越小越好（513330=0.049%，同类最优） |
| 规模变化 | 近1年规模增长（513330=+91.94亿→+50.76亿）趋势向下需注意 |
| 日均成交额 | 流动性指标（513330=31.73亿/日，可比第一） |

## 估值评价框架

对每条估值指标给出 0-10 分，然后汇总：

| 维度 | 评分标准 | 权重 |
|:----|:---------|:----:|
| PE历史分位 | ≤30%分位=9-10, 30-50%=7-8, >50%=5 | 30% |
| PB历史分位 | ≤10%分位=9-10, 10-30%=7-8, >30%=5 | 25% |
| 全球可比折价 | 折价>10%=8-10, 折价5-10%=6-7 | 20% |
| PEG匹配度 | <0.7=9-10, 0.7-1.0=7-8, >1.0=5 | 15% |
| 资金流向 | 持续净流入=8-10, 平稳=6, 流出=4 | 10% |

## 估值与技术的矛盾处理

当「估值面极低」与「技术面极弱」同时出现时（如513330案例）：

| 时间维度 | 估值面 | 技术面 | 实质 |
|:--------|:------|:------|:------|
| 长期(6-12月) | 历史底部区间 | — | 安全边际充足 |
| 短期(1-3月) | — | 下跌动能未衰竭 | 可能继续下跌 |

**操作框架**：将估值视为"安全边际上限"（决定值不值得买），将技术面视为"入场时机"（决定什么时候买）。两者矛盾时：

- 估值极度低估 + 技术面有背驰结构 = 配置窗口（如一买确认时）
- 估值极度低估 + 技术面无背驰 = 等待窗口（如513330现状，等金叉确认）
- 估值合理 + 技术面良好 = 持有窗口
- 估值高估 + 技术面出现一卖 = 卖出窗口

## 实战案例：513330 恒生互联网ETF（2026-06-15）

**估值总评：8.8/10（历史极低区间）**

| 维度 | 数据 | 得分 | 来源 |
|:----|:----|:----:|:-----|
| PE-TTM | 23.57倍，近10年26.64%分位 | 8 | 2026-06-04 申港证券研报 |
| PB | 2.38倍，近1年<2%分位 | 9.5 | 2026-06-09 新浪财经 |
| 全球可比折价 | 折价约12% | 8 | 申港证券 |
| PEG中位数 | 0.83 (<1) | 8.5 | 2026-01 东方财富 |
| 资金流向 | 连续融资净买入居可比基金第一 | 8 | 2026-06 东财新闻 |

> 注意：Tavily搜索的新闻有日期，提取估值数据时必须标注数据日期。不同日期的PB/PE会随指数涨跌变化（如PB从5月的2.46降至6月的2.38）。
