# 技术评分系统性异常（2026-05-29 起）

## 现象时间线

```
2026-05-06 ~ 05-27:  评分均值 82~85, A级占比 84~89%   ✅ 正常
─────────────────────────────────────────────────────
2026-05-29:          评分均值 66.7, A级占比 17.5%      ⚠️ 首次断崖下跌
2026-06-01:          评分均值 45.0, A级占比  0.0%      ❌ 崩溃（含 python3 路径 bug）
2026-06-03 (run 1):  评分均值 45.0, A级占比  0.0%      ❌ 崩溃（子进程未修复）
2026-06-03 (run 2):  评分均值 46.8, A级占比  4.2%      ❌ 子进程修复后仍异常
2026-06-05:          评分均值 48.6, A级占比  4.6%      ❌ 持续异常
```

**关键发现**: 5/29 的评分下降（66.7）发生在子进程 python 路径 bug（6/1）**之前**。说明存在两个独立问题:
- 问题 A: python3 路径 bug（已修复，issue #11）→ 表现为精确的 45.0/0%
- 问题 B: **评分算法/输入数据异常**（根因未明）→ 表现为评分均值 46-66，A级占比 0-17%

## 核心证据

### 1. C 级信号异常集中

2026-06-05 的 87 个信号中，**58 个（66.7%）为 C 级**，评分集中在 39-43 区间:

| 等级 | 信号数 | 均分 | 典型评分 |
|------|--------|------|----------|
| A+ | 1 | 97 | 97 |
| A | 3 | 80 | 75-82 |
| B+ | 13 | 68 | 65-71 |
| B | 7 | 60 | 55-63 |
| C+ | 5 | 50 | 49-51 |
| C | **58** | **40** | **39-43** |

评分 39 和 41 大量出现，这些似乎是评分因子的「保底基线值」。正常系统中多数信号应有 65+ 评分。

### 2. 评分与收益无相关性

| 周期 | r | 状态 |
|------|---|------|
| 5日 | +0.121 | ❌ < 0.3 |
| 10日 | +0.023 | ❌ < 0.3 |
| 20日 | **-0.079** | ❌ 负相关 |
| 60日 | **-0.280** | ❌ 强负相关 |

高评分信号（A+/A）的 20 日收益反而为负（-2.38%, -1.81%），而 C 级信号 +6.26%。

### 3. C 级信号反而表现最好

C 级（均分 40, 58 次）各周期收益:
- 5日: +4.31%, 10日: +4.95%, 20日: +6.26%, 60日: +6.34%

这组信号实际上盈利良好，但评分系统将所有信号打入低分区间。

## 可能根因猜想

| 可能性 | 依据 | 排除方法 |
|--------|------|----------|
| 评分因子权重偏移 | 评分集中在 39-43 基线，说明多数因子未触发 | 检查 `composite_scorer.py` 中各因子得分分布 |
| 价格缩放导致因子失效 | 5/29 前后可能有价格缩放变更 | 检查 calibrate_prices 的 scale_factor |
| 中枢扩展 P0 修复的副作用 | 修复日期 6/1 与实际崩溃日期 5/29 不完全吻合 | 确认修复代码实际部署日期 |
| 输入数据特征变化 | Baostock 返回数据变化导致因子计算异常 | 对比 5/27 和 5/29 的输入 K 线数据 |
| 评分阈值漂移 | config.yaml 中评分阈值被修改 | 检查 5/29 前后 config.yaml 变更 |
