## 修正后的判断逻辑

高笔数状态下是否超时，取决于以下两个变量的组合：

| 组合 | 结果 | 处理 |
|:-----|:-----|:-----|
| 笔数>40 + 30min数据失败 | **大概率超时** | 直接准备手动报告 |
| 笔数>40 + 30min数据成功 | **可能不超时** | 先尝试 quick 脚本（~30-40s完成） |
| 笔数<40 + 30min数据失败 | 可控 | 重试后成功 |
| 笔数<40 + 30min数据成功 | 正常 | 标准流程 |

## 实操建议（更新）

1. 检测到高笔数（>40）时，**先检查30min数据状态**（`.source_failed_*_30min.flag`是否存在）
2. 30min数据已成功获取 → 正常尝试 quick_chanlun + quick_html（并行后台，通常40s内完成）
3. 30min数据失败 → 按高预期超时处理，准备手动报告构建
4. **不要因"笔数>40"就跳过尝试**——鲁西化工证明30min数据成功时高笔数仍可快速完成
