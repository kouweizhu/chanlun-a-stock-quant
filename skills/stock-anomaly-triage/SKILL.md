# 股票异动归因三管齐下

当用户问某只个股当天为什么涨/跌时，采用三层并行排查，不串行。

## 工作流

### 并行排查（3路同时）

```
用户问"XX为什么涨/跌"
  ↓
并行启动三路：
├─ ① 资金面 + 行情：mx-financial-assistant
│   • 当日分时（大涨/大跌时点）
│   • 主力资金流向（净买入/卖出）
│   • 大单追踪（特大单/大单/中单）
│   • 成交量异常对比（vs 5日均量）
│
├─ ② 新闻+公告：同花顺 news-search（iwencai）
│   • 当日相关新闻（范围广但噪声多）
│   • 最新公告（业绩预告、增减持、合同签署等）
│   • 舆情关键词提取
│
└─ ③ 实时突发：web_search
    • Bing-cn 或 DuckDuckGo 搜"股票名 异动 原因"
    • 传闻/小道消息/盘中突发（任何单 skill 都不稳定覆盖）
    • Tavily 省着用（限次）
```

#### ① 资金面 + 行情 — 真实工具调用与检查点

```
# 路 1: 获取分时数据
分时数据 ← mx-financial-assistant.get_intraday(symbol="000001.SZ", date="2026-06-02")
# ✅ 验证：检查返回是否含 time / price / volume 字段
if 分时数据 is None or "time" not in 分时数据:
    标记此路为「⚠️ 无分时数据」，跳过资金面分析

# 路 1: 获取主力资金流向
资金流向 ← mx-financial-assistant.get_money_flow(symbol="000001.SZ", date="2026-06-02")
# ✅ 验证：检查返回是否含 net_inflow / large_order / medium_order
if 资金流向 is None or "net_inflow" not in 资金流向:
    标记此路为「⚠️ 无资金流向」，降权处理
# ✅ 归一化判断：net_inflow / turnover >= 5% 标记为显著主力行为
if 资金流向 and "net_inflow" in 资金流向 and "turnover" in 资金流向 and 资金流向["turnover"] > 0:
    inflow_ratio = abs(资金流向["net_inflow"]) / 资金流向["turnover"]
    if inflow_ratio >= 0.05:
        标记「💰 显著主力行为（净流向/成交额 ≥ 5%）」
    elif inflow_ratio >= 0.02:
        标记「💸 温和主力行为（净流向/成交额 2%-5%）」
    else:
        标记「🔹 主力行为不明显」

# 路 1: 获取成交量 vs 5日均量
volume_data ← mx-financial-assistant.get_volume(symbol="000001.SZ", days=5)
# ✅ 验证：检查返回是否含 avg_volume_5d / current_volume / volume_ratio
if volume_data is None or "avg_volume_5d" not in volume_data:
    检查边界条件：若上市≤20日 → 标注「📊 数据不足」，跳过 5日均量对比
# ✅ 量化阈值：volume_ratio > 1.5 标记为异常放量
if volume_data and volume_data.get("volume_ratio", 0) > 1.5:
    标记「📈 异常放量（量比 > 1.5）」— 成交量显著高于5日均量
elif volume_data and volume_data.get("volume_ratio", 0) < 0.5:
    标记「📉 异常缩量（量比 < 0.5）」— 成交量显著低于5日均量
else:
    标记「📊 量能正常」
```

#### ② 新闻+公告 — 真实工具调用与检查点

```
# 路 2: 搜索当日相关新闻
新闻列表 ← news-search.search(query="平安银行 2026-06-02", top_k=10)
# ✅ 验证：检查返回是否含 title / source / publish_time / snippet
if 新闻列表 is None or len(新闻列表) == 0:
    标记此路为「ℹ️ 当日无相关新闻」，聚合时排除
# ✅ 相关性过滤：title 或 snippet 含股票名/代码
else:
    相关新闻 = [n for n in 新闻列表 if "平安银行" in (n.get("title","") + n.get("snippet","")) or "000001" in (n.get("title","") + n.get("snippet",""))]
    if len(相关新闻) == 0:
        标记「⚠️ 搜索结果不直接相关（标题/摘要不含股票名或代码）」，聚合时降权
    else:
        新闻列表 = 相关新闻  # 替换为过滤后列表

# 路 2: 获取最新公告
公告 ← news-search.get_announcements(symbol="000001.SZ", date="2026-06-02")
# ✅ 验证：检查返回是否含 announcement_type / summary / publish_date
if 公告 is None or "announcement_type" not in 公告:
    标记此路为「ℹ️ 当日无新公告」
提取舆情关键词用于归因
```

#### ③ 实时突发 — 真实工具调用与检查点

```
# 路 3: 搜索引擎查找异动原因
try:
    ddg_results ← web_search.search(query="平安银行 异动 原因", source="duckduckgo", max_results=5)
    # ✅ 验证：检查返回是否含 title / url / snippet
    if ddg_results is None or len(ddg_results) == 0:
        bing_results ← web_search.search(query="平安银行 异动 原因", source="bing-cn", max_results=5)
        # ✅ 验证：同 ddg，若仍空则标记「🔍 未搜索到相关传闻」
        if bing_results is None or len(bing_results) == 0:
            标记此路为「🔍 无搜索发现」，聚合时排除
except TimeoutError:
    标记此路为「⏱️ 超时失败」，不阻塞其他路
except RateLimitError:
    sleep(2); retry一次；仍失败→标记「⚠️ 限流跳过」

# Tavily 仅在 Bing/DDG 均失败且配额充足时使用（有限次）
```

### 归因判断

三路结果回来后交叉验证：

```
证据强度排序：
  公告/官方 > 资金流向 > 高可信媒体 > 传闻/社交媒体

冲突解决规则（两路矛盾时）：
  1. 资金面与消息面矛盾（如资金净流入但消息面利空）→ 以消息面为准，标注「资金面滞后于消息面」
  2. 消息面内部矛盾（如公告利好但传闻利空）→ 以公告为准，传闻降权为「传闻仅供参考」
  3. 资金面与技术面矛盾（如主力流入但破位下跌）→ 优先技术面，标注「主力可能托盘或假拉升」
  4. 三路各执一词 → 输出「方向不明确，需观察后续确认」，不强行归因
```

**输出格式：**
```
[股票代码] [涨跌幅] [日期] [时间戳: YYYY-MM-DD HH:MM]
├─ 核心归因：一句话结论（确定性评分: 高/中/低）
├─ 路状态标记：
│   ├─ ① 资金面：[✅成功 | ⚠️降权 | ❌失败] — [主力净流入/出 + 大单动向 + 量能标记]
│   ├─ ② 消息面：[✅成功 | ⚠️降权 | ❌失败] — [公告/新闻/传闻]
│   └─ ③ 实时搜索：[✅成功 | ⚠️降权 | ❌失败] — [搜索发现摘要]
├─ 技术面：[关键价位/形态]
├─ 综合判断：[确定性 + 后续关注点]
└─ ⚠️ 风险提示：[潜在风险：如传闻未证实、数据延迟、主力行为存疑等]
```

## ⚠️ 失败模式

| 模式 | 表现 | 处理策略 |
|------|------|----------|
| **API 限流 (429)** | 工具返回 HTTP 429 或 rate-limit 错误 | 静默等待 1-2 秒后自动重试 1 次；仍失败则该路标记为「⚠️ 限流跳过」 |
| **超时 (timeout)** | 工具调用超过 15 秒无响应 | 立即标记该路为「⏱️ 超时失败」，不阻塞其他两路；聚合时排除该路 |
| **空结果** | 返回数据为空列表或 None | 聚合阶段直接排除该路；若三路均为空则输出「未找到明确归因」 |
| **鉴权失败 (401/403)** | API Key 无效或过期 | 检查环境变量是否存在，输出「🔑 鉴权失败，请检查 {变量名}」 |
| **数据格式异常** | 返回数据缺少关键字段 | 标记该路为「⚠️ 数据异常」，聚合时降权处理 |
| **服务不可用 (500/503)** | MCP 服务返回 HTTP 500 或 503，服务端异常 | 标记「🔴 服务端异常」，转用备选 MCP 或跳过该路；不阻塞其他路 |
| **股票代码未识别** | 用户输入股票名无法映射到标准代码，或接口返回「symbol not found」 | 尝试通过代码映射表模糊匹配（前缀/简称匹配）；若仍失败输出「⚠️ 未识别股票代码，请提供完整代码」 |
| **上下文截断** | 多路返回数据过多，超出 LLM 上下文窗口 | 摘要每路关键指标（Top-3 信号），丢弃低优先级细节；代码块压缩为单行关键值 |

## 🟡 边界条件

| 场景 | 表现 | 处理方式 |
|------|------|----------|
| **非交易日** | 当天为周末或法定节假日，无行情数据 | 跳过该路，在输出中标注「非交易日无数据」；可回查最近交易日 |
| **新股 / 次新股（上市≤20日）** | 无 5 日均量数据，量比不可计算 | 成交量异常判断标注「📊 数据不足（上市不足 20 日）」；仅用绝对值对比 |
| **一字板（涨停/跌停）** | 价格封板，成交量极低，无分时波动 | 特殊标记「🔒 一字板」，不分析分时波动；关注封单量和开板可能 |
| **停牌 / 退市整理期** | 当日无交易，行情接口返回空 | 跳过三路排查，直接输出「⚠️ 该股当日停牌 / 退市整理期，无交易数据」|
| **指数 / ETF** | 非个股，无资金流向和公告 | 跳过三路，转向宏观 / 板块归因路径 |
| **盘后无数据** | 盘后（15:00后）请求当日数据，部分接口已刷新 | 日期参数修正为 T-1 日，并标注「数据截至上一交易日」|

## 原则

1. **并行**：三路同时发，不要串行挨个等
2. **排序**：按证据强度降序排列原因，标出确定性
3. **诚实区分**：标注哪些是确认事实、哪些是市场传闻、哪些是推断
4. **搜索链**：Bing-cn → DDG → Tavily（Tavily 有次数限制，优先用前两个）

## 🚫 反例（常见错误做法）

| 错误做法 | 问题描述 | 正确做法 |
|----------|----------|----------|
| ❌ **只信一路就下结论** | 仅凭成交量放大就判定「主力拉升」，忽略资金流向和消息面 | 三路交叉验证，至少两路指向同一方向才能形成核心归因 |
| ❌ **传闻当事实** | 把股吧/社交媒体未证实消息直接作为归因输出 | 明确标注「市场传闻，未经证实」，按证据强度排序 |
| ❌ **忽略涨跌方向匹配** | 资金净流入但股价下跌，仍输出「主力资金流入利好」 | 归因必须与涨跌方向一致（涨→利好，跌→利空），矛盾时优先排查消息面 |
| ❌ **单一来源过度依赖** | 只用同花顺新闻搜索，遗漏突发消息 | 三管齐下：资金面 + 公告新闻 + 实时搜索，跨源交叉验证 |
| ❌ **数据不足仍强行归因** | 新股上市不足20日就用5日均量对比、停牌股分析分时波动 | 检查边界条件（🟡 边界条件表），数据不足时标注「数据不足」并跳过 |
