# 每月券商金股跟投验证

## 触发条件

每月5号前后（假期顺延至首个交易日后3天内），用户说"跑金股验证"/"本月金股"/"券商金股"时触发。

## 核心流程（4步）

```
Step 1 (insresearch)    Step 2 (business)    Step 3 (finance)    Step 4 (综合排序)
拉金股池 ──────→ 经营穿透过滤 ──────→ 6维度财务评分 ──────→ A+/A/B+分级
按推荐次数排序       排除纯概念股          扣非/增长/ROE        综合加权排序
预判推荐类型         TOP1<30%排除          毛利/负债/现金流
```

## Step 1: 拉取金股池 (hithink-insresearch-query)

### 关键查询写法

**必须在 query 中显式带年月**，否则默认返回上月数据：

```
query = "2026年6月 券商金股"   # ✅ 正确
query = "券商金股"             # ❌ 返回上月缓存数据
query = "202606 金股"          # ❌ 返回0条
```

### API 调用

用 Python urllib（不用 curl，避免引号嵌套），分页拉取全量：

```python
import json, urllib.request, secrets, os

api_key = os.environ.get('IWENCAI_API_KEY')  # 或从 ~/.bashrc 读取
url = 'https://openapi.iwencai.com/v1/query2data'

# ⚠️ 年月必须动态生成，不要硬编码
year_month = f"{year}年{month}月"
query = f"{year_month} 券商金股"

# 分页拉取（每页50，通常1-4页够用）
all_datas = []
for pg in range(1, 6):
    r = query_page(query, page=str(pg), limit='50')
    datas = r.get('datas', [])
    if not datas: break
    all_datas.extend(datas)
    if len(datas) < 50: break
```

### 返回字段

| 字段 | 用途 |
|------|------|
| `股票代码` / `股票简称` | 标的标识 |
| `研究机构` | 券商名称 |
| `推荐理由` | 判断推荐类型（基本面/题材/价值/成长） |
| `组合名称` | 区分金股组合/行业金股/策略报告 |
| `组合时间` | YYYYMM格式，确认是目标月份 |
| `报告摘要` | 策略观点全文 |

### 推荐次数统计

同一只股票可能出现在多个组合（金股组合、行业金股、策略报告等），每个 entry 算一次推荐。去重后按推荐次数降序排列。

### 推荐类型预判

| 推荐理由关键词 | 判断 |
|---------------|------|
| "ROE提升""毛利率改善""市占率提升""成本下降" | ⭐ 基本面驱动 |
| "受益于XX政策""XX概念""题材催化" | ⚠️ 题材驱动 |
| "估值低位""安全边际""高分红""回购" | ✅ 价值驱动 |
| "新业务拓展""第二增长曲线""产能释放" | ⭐ 成长驱动 |

## Step 2: 经营穿透 (hithink-business-query)

### 查询

逐只查询（每次1只），用产品分类：

```
query = "{股票名称} 产品分类 主营业务构成"
```

### 过滤标准

| 判断 | 条件 | 处理 |
|------|------|------|
| ❌ 排除 | TOP1产品收入占比 < 30% 且业务分散 | 无清晰主业 |
| ⚠️ 存疑 | TOP1占比 30-50%，或主营与推荐概念不匹配 | 需人工确认 |
| ✅ 通过 | TOP1占比 > 50%，且与推荐概念一致 | 进入Step 3 |
| ⭐ 优质 | TOP1占比 > 60%，且行业景气度向上 | 加分 |

**特殊行业处理：**
- 金融行业（券商/银行）：收入天然分散，TOP1占比低属正常，不作为排除依据
- 资源类公司（矿业/有色）：多品类经营，TOP1可能低于50%，结合行业判断

**⚠️ 数据坑：** business-query 经常返回"地区分类"而非"产品分类"。重试加 `产品分类` 关键词。

## Step 3: 6维度财务评分 (hithink-finance-query)

### 评分模型

| 维度 | 达标条件 | 含义 | 权重 |
|------|---------|------|------|
| 扣非>营收 | 扣非净利润增速 > 营业收入增速 | 利润质量 | 1分 |
| 高增长 | 扣非净利润增速 > 20% | 成长性 | 1分 |
| ROE | 加权ROE > 15%（Q1放宽到10%） | 资本回报 | 1分 |
| 毛利率 | 销售毛利率 > 30% | 护城河 | 1分 |
| 负债率 | 资产负债率 < 60% | 财务安全 | 1分 |
| 现金流 | 经营活动现金流净额 > 0 | 现金质量 | 1分 |

满分6分。评级：5-6分⭐精选 / 3-4分✅合格 / 1-2分⚠️谨慎 / 0分❌排除

### 查询方式

分批查询（5只/批 × 3指标），两轮覆盖6个维度：

```python
# Round 1: 扣非增速 + 营收增速 + ROE
query = "300308.SZ 002475.SZ ... 扣非净利润同比增长率 营业收入同比增长率 加权净资产收益率ROE"

# Round 2: 毛利率 + 负债率 + 现金流
query = "300308.SZ 002475.SZ ... 销售毛利率 资产负债率 经营活动产生的现金流量净额"
```

### 关键 Pitfalls

| 问题 | 解法 |
|------|------|
| 现金流字段返回全0 | 必须用完整名称 `经营活动产生的现金流量净额`，简称不生效 |
| 扣非增速格式混乱 | abs值<10则为小数形式（×100转百分比），否则已是百分比 |
| Q1单季ROE普遍偏低 | Q1 ROE阈值从15%放宽到10%，或用年化×4估算 |
| 周期股Q1数据失真 | 锂/铝/煤/钼的Q1扣非可能大幅波动，需结合一致预期 |
| 5只/批超限返回0条 | 严格控制每批≤5只股票、≤3个指标 |
| 字段间比较不支持 | query2data 不支持"扣非>营收"这种比较，需本地Python计算 |

### 万华化学等特殊标的

如某只高推荐标的财务评分异常低（如万华化学6家推荐但0/6），大概率是数据合并问题或查询未命中。**对≥5家推荐但评分≤2的标的，必须单独补查确认。**

## Step 4: 综合排序与分级

### 排序公式

```
综合得分 = 机构共识度(推荐次数/最高次数×100) × 30%
         + 经营穿透(⭐=100, ✅=67, ⚠️=33) × 20%
         + 财务评分(得分/6×100) × 50%
```

### 分级标准

| 等级 | 条件 | 含义 | 操作 |
|------|------|------|------|
| **A+** | 综合≥75 且 财务≥5/6 | 重点配置 | 纳入缠论监控 |
| **A** | 综合≥60 且 财务≥3/6 | 积极关注 | 加入观察池 |
| **B+** | 综合≥50 | 适度关注 | 仅参考 |
| **B** | 综合<50 | 暂不推荐 | 排除 |

### 与缠论系统衔接

A+级标的直接导入缠论三买扫描器候选池：
```
金股池(全量) → 经营+财务验证 → A+精选池(4-6只) → chanlun-core三买扫描
```

## 输出报告格式

报告保存到 `/mnt/d/常用文件/每月券商金股/{年}年{月}月券商金股跟投验证报告.md`

包含七章：
1. 金股池概览（共识度TOP + 行业分布）
2. 经营穿透结果（通过/排除/待复核）
3. 6维度财务评分明细表
4. A+/A/B+/B 四级精选池
5. 关键发现（3-5条）
6. 风险提示
7. 缠论衔接建议

## 历史验证数据参考

2026年5月首次验证结果：
- 输入：38家券商、293只去重A股（研报提取）/ 147只（结构化数据）
